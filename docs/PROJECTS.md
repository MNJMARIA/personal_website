# Проєкти на сайті: як це працює

Сайт хоститься на **GitHub Pages** (безкоштовно), деплой робить GitHub Actions.
Розділ «Проєкти» читає `projects.json`, який збирається при кожному деплої з двох джерел:

| Джерело | Де лежить | Як змінюється |
|---|---|---|
| Ручні проєкти (з фото, галереєю) | `data/projects.manual.json`, фото в `images/` | кнопка **«+ Додати проєкт»** на сайті або правка JSON |
| Репозиторії GitHub | `data/approved/<repo>.json` (мінімум `{"repo": "..."}`) | автоматично через Pull Request |

## Позначити репозиторій для сайту
1. На сторінці репозиторію GitHub натисни ⚙ біля **About** і додай тему (topic) **`portfolio`**.
2. Протягом ≤3 годин (або вручну: Actions → *Propose new projects* → Run workflow) у цьому репозиторії з'явиться Pull Request
   **«Додати на сайт: …»** з прев'ю картки. GitHub надішле сповіщення (пошта / мобільний застосунок GitHub).
3. **Merge** - проєкт з'явиться на сайті за 1-2 хв. **Close** - відхилено (його більше не пропонуватимуть; передумала - Reopen + Merge).

Після підтвердження все синхронізується саме:
* змінила опис репозиторію або README → короткий опис, теги і дата «Оновлено» оновляться (щодня вночі або після будь-якого пушу в цей репозиторій);
* видалила репозиторій або зняла тему `portfolio` → проєкт зникає з сайту.

Короткий опис = опис репозиторію (About) або перший абзац README (до 180 символів). Повний опис на сторінці проєкту = перші 2 абзаци README.
**Фото.** Картинки з README (`![](...)` та `<img>`; бейджі, іконки й логотипи з назвою `icon`/`logo` ігноруються)
підтягуються автоматично. Під час кожного деплою вони **завантажуються на сайт у вихідній якості, без стиснення**
(`media/<проєкт>/…`), тож замінила скриншот у README - на сайті з'явиться новий після наступного деплою (щодня вночі
або вручну через Actions). Головним фото стає широка картинка, а якщо всі скриншоти вертикальні, перший показується
повністю (без обрізання). Решта (до 12) - карусель; клік по центральному фото відкриває його на весь екран.
Свої фото можна вказати вручну через `cover` та `gallery` (вони мають пріоритет).

**Можливості.** Якщо в README є розділ «Можливості» / «Features» (або «Функціонал»), з нього генерується окремий список
«Основні можливості» на сторінці проєкту: за підрозділами `###` (назва + перше речення) або за пунктами списку.
Свій список можна задати полем `"features": {"ua": ["…"], "en": ["…"]}` у `data/approved/<repo>.json`.

**Фото з папок.** Якщо в README картинок немає, автоматика шукає їх у папках `screens`, `screenshots`, `img`, `images`,
`docs/...` тощо (файли від 5 КБ, без іконок і логотипів). У Pull Request вони показуються мініатюрами й питання
«Додати ці фото?»: **Merge** - так (перше стане головним, решта піде в карусель); щоб відмовитись, у
`data/approved/<repo>.json` постав `"photos": "none"`. Режими `photos`: `auto` (README, а якщо порожньо - папки;
за замовчуванням), `readme` (лише README), `none` (без фото).

**Як замінити головне фото картки.**
* Фото вже є в репозиторії проєкту: `"cover": "repo:images/Star_schema.jpg"` (шлях від кореня репозиторію проєкту).
* Своє нове фото: додай файл у папку `images/` цього репозиторію (сайту) і вкажи `"cover": "images/my.jpg"`.
  Решта фото залишаються каруселлю; щоб задати їх самій - `"gallery": ["repo:images/a.jpg", "images/b.jpg"]`.
Правиш файл `data/approved/<repo>.json` прямо на GitHub (Edit file → Commit) - сайт оновиться за 1-2 хв.

**Переклад.** Опис, короткий опис і «Основні можливості» автоматично перекладаються на українську й англійську
(офлайн-модель Argos Translate, безкоштовно; перший запуск ставить модель 1-3 хв, потім береться з кешу). Перекладається
лише та мова, якої немає: англійський README → українська версія автоматично, і навпаки. Якість - рівень
машинного перекладу; для ідеального тексту задай `title`/`summary`/`description` у форматі `{"ua": "...", "en": "..."}` -
твій текст завжди має пріоритет. Якщо модель недоступна, сайт збирається як завжди (текст лишається мовою оригіналу).
Вимкнути переклад: змінна `TRANSLATE=off` у workflow.

**Навички.** Технології проєкту (теми репозиторію, мови) автоматично додаються в розділ «Навички» у відповідну
категорію, якщо їх там ще немає. Довідник технологій і категорій - `data/skill-catalog.json` (додай рядок, якщо
технології немає), твої основні пункти - `data/skills.json`. У `data/skills.json` поле `"ignore": ["Gradle"]` не
пускає технологію на сайт; для окремого проєкту: `"skills": false` (нічого не додавати) або `"skills": ["Dart", "Flutter"]`
(лише ці). У Pull Request видно, які навички буде додано.

Щоб задати свій текст/назву/обкладинку/двомовність, відредагуй `data/approved/<repo>.json`:
```json
{
  "repo": "MNJMARIA/my-project",
  "title":       {"ua": "Назва", "en": "Title"},
  "summary":     {"ua": "Коротко", "en": "Short"},
  "description": {"ua": "Довгий опис", "en": "Long description"},
  "cover": "images/my-project.jpg",
  "gallery": ["images/a.jpg", "images/b.jpg"]
}
```

## Кнопка «Додати проєкт» (тільки для власниці)
1. Створи токен: GitHub → Settings → Developer settings → Fine-grained tokens → *Generate new token*:
   Repository access = **Only select repositories → personal_website**, Permissions → **Contents: Read and write**. Термін дії - до 1 року.
2. Відкрий `https://<твій-сайт>/#admin`, встав токен. Він зберігається лише в цьому браузері; без нього кнопки немає.
3. «+ Додати проєкт» → назва, опис, технології, головне фото й додаткові → **Зберегти**.
   Фото зберігаються в оригінальній якості (стискаються лише файли понад 6 МБ), усе потрапляє в репозиторій одним комітом, сайт оновлюється за 1-2 хв.

## Одноразове налаштування репозиторію
1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. **Settings → Actions → General → Workflow permissions:** *Read and write permissions* і галочка
   **Allow GitHub Actions to create and approve pull requests**.
3. Запусти *Deploy site to GitHub Pages* вручну (Actions → Run workflow). Адреса: `https://<user>.github.io/personal_website/`
   (якщо перейменувати репозиторій на `<user>.github.io`, адреса буде `https://<user>.github.io/`).
4. Коли новий сайт перевірено - Netlify можна вимкнути.

Примітка: GitHub вимикає заплановані workflow у публічних репозиторіях без активності ~60 днів - тоді просто натисни *Enable workflow* на вкладці Actions.
